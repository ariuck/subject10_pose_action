# Day 03 — bend_pose.jpg Left / Right 관절 확인

## 결론

`bend_pose.jpg`의 **왼팔꿈치 각도는 잘못 검출된 값이므로 SKIP** 하고 분석에 사용하지 않는다.

| 관절 | 코드 출력 | 최종 기록 | 판단 |
|---|---|---|---|
| left_elbow_angle | 155.81° | **SKIP** | 틀림 — 왼팔 관절이 오른팔 위에 찍힘 |
| right_elbow_angle | 158.53° | 158.53° | 맞음 |
| left_knee_angle | 174.52° | 174.52° | 맞음 |
| right_knee_angle | 173.93° | 173.93° | 맞음 |

## 1. 실행 결과

```bash
python scripts/12_joint_angle.py --source data/day03/images/bend_pose.jpg
```

| 관절 | Confidence | 코드 출력 |
|---|---|---|
| 왼쪽 팔꿈치 (어깨 0.974 / 팔꿈치 0.817 / 손목 0.884) | 모두 0.50 이상 | 155.81° |
| 오른쪽 팔꿈치 (어깨 0.998 / 팔꿈치 0.992 / 손목 0.979) | 모두 0.50 이상 | 158.53° |
| 왼쪽 무릎 | 모두 0.96 이상 | 174.52° |
| 오른쪽 무릎 | 모두 0.97 이상 | 173.93° |

필요한 관절의 Confidence가 모두 0.50 이상이라 코드에서는 SKIP 없이 네 각도가 모두 계산되었다.

## 2. 실제 사진과 비교

왼쪽 관절은 빨간색, 오른쪽 관절은 파란색으로 다시 그려서 확인했다.

- `reports/day03/images/bend_pose_left_right.jpg`
- `reports/day03/images/bend_pose_arm_zoom.jpg`

사진 속 사람은 화면 오른쪽을 보고 허리를 숙이고 있다. 이 방향에서는 사람의 **오른쪽 몸이 카메라 쪽**을 향한다.

- 오른쪽 귀·눈 Confidence가 0.97~0.98로 높고, 왼쪽 귀는 0.18로 낮은 것도 이 방향과 일치한다.

| 부위 | 실제 사진 | Pose 결과 | 판단 |
|---|---|---|---|
| 오른팔 | 카메라 쪽 팔. 앞으로 길게 뻗어 손이 화면 오른쪽 아래에 있음 | 어깨·팔꿈치·손목이 이 팔 위에 정확히 찍힘 | 맞음 |
| 왼팔 | 몸 반대편에서 아래로 늘어져 있고, 손이 허벅지 옆에 보임 | 팔꿈치·손목이 **오른팔 위(위팔 중간, 아래팔 중간)**에 찍힘 | **틀림 → SKIP** |
| 오른다리 | 카메라 쪽 다리, 앞쪽 신발 | 카메라 쪽 다리에 찍힘 | 맞음 |
| 왼다리 | 반대쪽 다리, 뒤쪽 신발 | 반대쪽 다리에 찍힘 | 맞음 |

즉 왼팔은 실제 위치가 아니라 보이는 오른팔을 따라 한 번 더 찍혔다. 화면에는 두 팔 Skeleton이 같은 팔 위에 겹쳐 그려진다.

## 3. SKIP 한 이유

- 코드가 출력한 `left_elbow_angle = 155.81°`는 실제 왼팔의 각도가 아니다. 오른팔 위에 잘못 찍힌 세 점으로 계산한 값이다.
- 그래서 왼팔꿈치와 오른팔꿈치 각도가 비슷하게(155.81° / 158.53°) 나왔지만, 두 팔이 실제로 비슷하게 펴져 있다는 뜻이 아니다.
- 왼팔꿈치 0.817, 왼손목 0.884로 Confidence가 기준 0.50보다 높아서 12번 코드의 Confidence 검사로는 걸러지지 않았다.
- 틀린 좌표로 계산한 각도를 그대로 쓰면 이후 Feature와 동작 분석에 잘못된 값이 들어가므로, 결과 이미지를 확인한 뒤 직접 SKIP 처리했다.

## 4. 코드에 SKIP 규칙 추가

`scripts/12_joint_angle.py`에 "겹쳐 찍힌 팔·다리 검사"를 추가했다.

- 왼팔(다리)의 가운데·끝 관절이 오른팔(다리) 선 위에 거의 붙어 있는지 확인한다.
- 거리 평균을 팔다리 길이로 나눈 값(`overlap`)이 0.05보다 작으면 같은 팔다리를 두 번 찍은 것으로 본다.
- 이때 가운데·끝 관절 Confidence 평균이 더 낮은 쪽 각도를 SKIP 한다.
  (bend_pose: 왼팔 0.85 / 오른팔 0.99 → 왼팔 SKIP)

```text
left_elbow_angle    : SKIP (right_elbow와 겹쳐 찍힘, overlap=0.035)
right_elbow_angle   :  158.53°
left_knee_angle     :  174.52°
right_knee_angle    :  173.93°
```

3일차 이미지 8장에 다시 실행했을 때 SKIP 된 것은 bend_pose의 왼팔꿈치 하나뿐이고, 나머지 각도는 이전과 같았다.

기준값 0.05는 bend_pose에서 잘못 찍힌 왼팔(0.035)과 실제로 나란히 선 두 다리(약 0.085) 사이로 정했다.

### 규칙의 한계

- 2일차 `side.jpg`(발을 모으고 옆으로 선 사진)에서는 오른무릎이 SKIP 되었다(overlap=0.040). 카메라 반대쪽 다리가 앞쪽 다리 뒤에 완전히 가려져 위치를 확인할 수 없는 경우라, 틀렸다고 단정할 수는 없지만 확인할 수 없으므로 SKIP 해도 되는 경우이다.
- 1일차 Challenge `side.jpg`(팔을 뒤로 뻗은 사진)의 오른팔꿈치는 손목이 어깨 옆에 잘못 찍혀 4.91°가 나왔지만 이 규칙으로는 잡히지 않는다. 두 팔이 겹친 것이 아니라 팔 하나의 위치가 틀린 경우이기 때문이다.
- 따라서 이 규칙은 결과 이미지 확인을 대신하지 못하고, 측면 자세에서 자주 생기는 "반대쪽 팔다리 겹침"만 자동으로 걸러 준다.

## 5. 정리

- Confidence가 높다고 관절 위치가 맞는 것은 아니다. 2일차에 배운 "Confidence ≠ 정답(Ground Truth)"이 실제로 나타난 사례이다.
- 측면 촬영에서는 카메라 반대쪽 팔·다리가 몸에 가려져, 모델이 보이는 쪽 팔다리에 반대쪽 관절을 겹쳐 찍을 수 있다.
- 측면 자세의 Feature를 만들 때는 카메라 쪽 관절(이 사진에서는 오른쪽)을 우선 사용하고, 반대쪽 관절각도는 결과 이미지를 직접 보고 맞는지 확인한 뒤 사용한다. 틀린 경우에는 SKIP 한다.
- 정면 사진(`sit_pose`, `left_arm_up`, `right_arm_up`, `arms_up_person_a`)은 Left / Right가 모두 사람 본인 기준으로 맞게 찍혔다. (`reports/day03/images/front_view_left_right.jpg`)
