# Day 07 Processing FPS Check

## Saved Video

사용한 영상:
- 교재 `S02_A003_T01.mp4` (25 FPS, 9.64초)
- 3팀 `S05_A007_T01.mp4` (60 FPS, 1080×1920 세로, 10.93초). 학습에 쓰지 않은 사람의 영상이다. (팀 ID 통일 후 S05가 바뀌어 다시 측정)

평균 Processing FPS:

| 영상 | 원본 FPS | 처리 FPS (42번 마지막 출력) | 처리 FPS 평균 (43번 요약) |
|---|---:|---:|---:|
| S02_A003_T01 기본 설정 | 25 | 37.08 | 61.36 |
| S05_A007_T01 기본 설정 (3팀 모델) | 60 | 22.09 | 25.02 |
| S05_A007_T01 Threshold 0.20 (3팀 모델) | 60 | 23.10 | 25.64 |

- 42번 마지막 줄의 `Overall processing FPS`는 처리한 Frame 수를 전체 처리 시간으로 나눈 값이다. 결과 MP4를 쓰는 시간까지 포함된다.
- 43번의 `mean_processing_fps`는 Frame마다 기록한 처리 FPS의 평균이다.
- 같은 실행인데 두 값이 다르므로, 비교할 때는 같은 종류의 값끼리 본다.
- 교재 예시는 49.78이었다. 컴퓨터마다 다를 수 있는 값이다.

느리다고 느껴졌는가:
- 교재 영상은 원본 25 FPS보다 빠르게 처리됐다.
- 3팀 영상은 원본이 60 FPS인데 약 22 FPS로 처리됐다. 실시간이었다면 원본 속도를 따라가지 못하는 셈이다.
- 3팀 영상은 1080×1920으로 해상도가 더 크다. Skeleton과 글자를 그린 결과 MP4를 같은 크기로 저장하는 작업도 더 무겁다.

## 원인을 구분해 봅니다

카메라·네트워크 문제로 보이는가:
- 연결 확인 때 `Stream ends prematurely` 메시지가 한 번 나왔다. 폰 화면이 꺼지거나 앱이 뒤로 가면 Stream이 끊기므로, 이것은 AI 처리가 아니라 카메라 쪽 문제다.

AI Processing 문제로 보이는가:
- 저장영상에서는 해상도가 큰 3팀 영상(1080×1920)이 교재 영상보다 확실히 느렸다. Pose 추론과 화면 그리기가 Frame 크기의 영향을 받는다.
- Random Forest 예측은 0.25초에 한 번만 하므로, 매 Frame 처리 속도에는 Pose 쪽 영향이 더 크다고 생각한다.

Sliding Window 때문에 기다린 것으로 보이는가:
- 모든 저장영상에서 첫 예측은 4.0초에 나왔다. 처리 속도와 상관없이 Window 5초 × 0.8을 채울 때까지 기다린 것이다.


## 한 줄 정리

- 예측이 늦게 시작되는 4초는 Sliding Window 때문이다. 처리 FPS는 입력 해상도의 영향을 크게 받았다. IP Webcam의 지연은 테스트 후 네트워크 쪽과 나누어 확인할 예정이다.
