흐름도: `3팀_Action_학습파이프라인.png`, 파일추적표: `3팀_파일추적표.md`

## 1. 5일차에 Keypoint 원본을 저장하고 6일차에 다시 Feature를 만드는 이유는 무엇인가요?

5일차 26번은 관절의 Pixel 좌표·이미지 정규화 좌표·Confidence를 **가공하지 않고** 저장한다.
이렇게 하면 QA(27번)에서 관절별 Confidence로 품질을 검사할 수 있고, 6일차에서 Feature 계산 방법을 바꿀 때(Step 수, 각도 포함 여부, 팀 Feature 추가 등) **영상에서 YOLO를 다시 돌리지 않고** Keypoint CSV만 다시 읽어 새로 만들 수 있다.
실제로 6일차 38·39번 비교 실험과 3팀 45-D 실험도 같은 Keypoint CSV에서 Feature만 바꿔 계산했다.
처음부터 38-D만 저장했다면 원본 좌표가 사라져 다른 방식으로 다시 계산할 수 없다.

## 2. 4일차 22번에서 이미 만든 38-D Sequence와 5·6일차 데이터셋은 어떤 관계인가요?

**계산 방법은 같고, 데이터와 역할이 다르다.**
4일차 22번은 한 사람의 6개 영상을 Frame마다 38-D(정규화 좌표 34 + 각도 4)로 바꿔, Sequence가 무엇인지 이해하기 위한 결과였다.
5·6일차는 3명의 18개 영상으로 원본 Keypoint를 먼저 저장하고 QA·승인·사람 기준 Split을 거친 뒤, 6일차 `src/sequence_utils.py`가 **같은 38-D 계산**(같은 `normalize_by_shoulder_width`, `selected_joint_angles`)을 다시 하고 30 Step으로 맞춰 1,140개 숫자로 만든다.
그래서 4일차 결과 파일은 6일차 학습에 직접 쓰이지 않고, 4일차에서 배운 계산 방법만 이어진다.

## 3. Validation과 Test를 모델 학습에 섞으면 왜 문제가 될까요?

Validation(S02)과 Test(S03)는 **학습에 쓰지 않은 사람**에게서 모델이 잘 동작하는지 보려고 남겨 둔 데이터다.
이 데이터를 학습에 넣으면 모델이 그 사람의 체형·동작 습관까지 외워 점수가 실제보다 높게 나오고(Data Leakage), 처음 보는 사람에 대한 성능을 알 수 없게 된다.
Validation은 조건(Feature, 설정)을 고를 때만, Test는 조건을 정한 뒤 **마지막에 한 번만** 사용해야 Test 점수를 믿을 수 있다.
5일차 32번에서 Frame을 랜덤으로 나눴을 때 3명·18개 Clip이 모두 Train과 Test에 섞이는 것을 직접 확인했다.

## 4. `.pt`와 `.joblib`은 이번 프로젝트에서 역할이 어떻게 다른가요?

| | `yolo11n-pose.pt` | `rf_action_baseline.joblib` |
|---|---|---|
| 무엇인가 | 미리 학습된 **YOLO Pose 모델** (PyTorch) | 우리가 6일차 35번에서 **직접 학습한 Random Forest** (scikit-learn) |
| 입력 | 영상 Frame (이미지) | Clip 하나의 1,140개 숫자 Feature |
| 출력 | 사람 BBox + COCO 17 관절 좌표·Confidence | Action 이름 (bend_return ~ wave) |
| 사용하는 코드 | 26번 (Keypoint 추출) | 36번(Validation), 40번(Test) |

즉 `.pt`는 **"관절이 어디 있는가"**를 찾고, `.joblib`은 그 관절 움직임을 보고 **"어떤 동작인가"**를 판단한다.

## 5. 최종 혼동행렬에서 실제 정답과 AI 예측은 어떤 파일에서 왔나요?

- **실제 정답**: `configs/action_classes.csv`의 `action_label`에서 시작해 26번 Keypoint CSV → 29번 승인 목록 → 30번 `data/day05/splits/test.csv` → 34번 `data/day06/sequences/test.csv`의 `action_label` 열로 이어진다. 40번이 이 열을 `y_true`로 읽는다.
- **AI 예측**: 40번이 `data/day06/sequences/test.csv`의 1,140개 Feature를 `artifacts/day06/rf_action_baseline.joblib`(Feature 순서는 `rf_feature_columns.json`)에 넣어 `model.predict()`로 만든 `y_pred`다.
- 두 값을 비교한 결과가 `reports/day06/metrics/test_predictions.csv`(`true_label`, `pred_label`)와 `reports/day06/confusion/test_confusion_matrix.png`에 저장된다. (이번 S03 Test: 6개 모두 정답, Accuracy 1.0)
