### 문제 1-2. 한 영상의 정답 추적 — `S03_A006_T01.mp4`

1. `S03`이 뜻하는 것: **세 번째 Subject(촬영한 사람 3번)**. 5일차 Split에서 Test에 들어가는 사람이다.
2. `A006`이 뜻하는 것: **여섯 번째 Action의 ID**.
3. 정답 동작 이름: **`wave`**. `configs/action_classes.csv`의 `action_id`가 `A006`인 행의 **`action_label` 컬럼**에서 확인했다.
   (이 값은 이후 Keypoint CSV, Approved Manifest, Split CSV, 6일차 Sequence CSV의 `action_label` 컬럼에 그대로 이어진다.)
4. 정답은 **미리 작성된 기준표를 읽어서 붙인다.**
   - 근거: `26_extract_keypoint_dataset.py`의 `load_action_map()`이 `action_classes.csv`를 읽어 `{"A006": "wave", …}` 표를 만들고,
     `parse_clip_name()`이 파일명에서 정규표현식으로 `A006`을 꺼낸 뒤 그 표에서 `action_label`을 찾는다.
   - YOLO Pose(`model.predict`)는 사람의 관절 좌표와 Confidence만 출력하고, 동작 이름은 예측하지 않는다.

> **생각해 볼 문제 — `project.json → action_classes.csv → MP4` 순서로 변환되는가?**
> 아니다. 세 파일은 서로를 변환해서 만들어지는 관계가 아니라, **26번 프로그램 하나가 서로 다른 입력 세 개를 함께 사용**하는 구조다.
> `project.json`은 YOLO를 어떻게 실행할지(설정), `action_classes.csv`는 정답을 무엇으로 붙일지(라벨), MP4는 무엇을 분석할지(영상)를 각각 알려 준다.

### 문제 2-2. 5일차 Keypoint CSV 컬럼

`26_extract_keypoint_dataset.py`의 `build_keypoint_columns()`와 `fieldnames` 목록에서 확인했다.

  (검산: `head -1 data/day05/keypoints/S03/wave/S03_A006_T01.csv | tr ',' '\n' | wc -l` → 95)
- 정답을 저장하는 컬럼 이름: `action_label`

**탐구 질문 — 26번 CSV를 곧바로 `38-D Feature CSV`라고 불러도 될까?**
안 된다. 26번 코드는 `src/feature_utils.py`의 정규화·각도 함수를 불러오지 않고(`import`가 `load_config`, `resolve_device`, `COCO_KEYPOINT_NAMES`뿐),

### 문제 3-1. Human QA의 위치

1. 자동 QA에서 `AUTO_PASS`가 나왔다면 사람은 전혀 확인하지 않아도 되나요?
   → **아니다.** AUTO_PASS는 "자동 기준에서 문제를 못 찾았다"는 뜻이지 최종 승인이 아니다. 교재 설명상 필수 확인 대상은 CHECK이고 AUTO_PASS는 표본 확인을 권장하지만,
   실제 28·29번 코드는 모든 Clip의 `human_decision`이 입력되어야 통과하고 **PASS만 승인**한다. 그래서 이번 실습에서는 AUTO_PASS 13개도 직접 보고 PASS로 기록했다(처음에는 Approved가 5개만 나왔다).
2. 사람이 `PASS / RESHOOT / EXCLUDE`를 입력하는 파일: **`data/day05/qa/keypoint_clip_review.csv`** (`human_decision`, `human_note` 컬럼)
3. 최종 승인 목록 CSV를 생성하는 Python 파일: **29번** `29_build_approved_manifest.py`

### 문제 3-2. 두 종류의 `test.csv`

| 비교 항목 | 5일차 `splits/test.csv` | 6일차 `sequences/test.csv` |
|---|---|---|
| 생성 Python 코드 번호 | 30번 | 34번 |
| 전체 상대 경로 | `data/day05/splits/test.csv` | `data/day06/sequences/test.csv` |
| CSV 한 행이 나타내는 것 | 승인된 **Clip 하나의 정보** (Subject, Action, 영상·Keypoint 경로, QA 값, Human QA 결과) | **Clip 하나 전체의 움직임을 30 Step으로 맞춘 숫자 Feature** (메타 8열 + Feature 1,140열) |
| 원본 Keypoint CSV 경로가 들어 있나요? | **있다** (`keypoint_csv`, `video_path`) | **없다** |
| 1,140개 모델 입력 Feature가 들어 있나요? | **없다** | **있다** (`t00_nose_x` ~ `t29_right_knee_angle`) |
| 실제 동작 정답(`action_label`)이 들어 있나요? | 있다 | 있다 |

**왜 같은 `test.csv`라는 이름이어도 서로 다른 두 파일이 필요한가?**
5일차 `splits/test.csv`는 "**어떤 Clip이 Test인지와 원본이 어디 있는지**"를 정하는 목록이고, 6일차 `sequences/test.csv`는 그 목록의 Keypoint를 읽어 만든 "**모델이 바로 읽을 수 있는 숫자 입력**"이다.
목록과 입력을 나눠 두면 Split은 그대로 둔 채 Feature 계산 방식(Step 수, Feature 구성)만 바꿔 다시 만들 수 있고, 오분류가 나오면 목록의 경로로 원본까지 되돌아갈 수 있다(37번).

### 문제 4-1. 숫자 Feature 계산식

```text
Frame 하나 = (관절좌표 34개) + (관절각도 4개)
           = 38-D Feature

Clip 하나  = 30 Step × 38-D Feature
           = 1,140개 숫자
```

- 공통 함수 파일: `src/sequence_utils.py` (`frame_feature_from_row`, `build_frame_feature_matrix`, `resample_sequence`, `flatten_sequence`)
- 실행 Python 파일: `scripts/34_build_sequence_dataset.py` (Train / Validation / Test 각 6개 Clip을 변환해 `data/day06/sequences/`에 저장)

### 문제 4-3. 정답 누출 여부

1. `X_train`에 `action_label`을 넣어도 될까요?
   → **안 된다.** 정답을 입력에 넣으면 모델이 움직임이 아니라 정답 열을 보고 맞히게 된다(시험지에 답을 적어 주는 것). 35번은 `feature_columns()`로 메타데이터를 빼고 1,140개 Feature만 `X_train`으로 쓴다.
2. `y_train`에는 어떤 값이 들어가야 하나요?
   → Train Clip(S01)마다의 **실제 동작 이름**, 즉 `train.csv`의 `action_label` (bend_return, …, wave).
3. `X_test`와 `y_true`는 어떤 점이 다른가요?
   → `X_test`는 모델에 넣는 **1,140개 숫자 Feature**이고, `y_true`는 모델에 넣지 않고 **채점에만 쓰는 실제 정답**(`test.csv`의 `action_label`)이다.
4. Test에서 만들어진 실제 정답·예측·정오답 비교 CSV의 경로는?
   → `reports/day06/metrics/test_predictions.csv` (`true_label`, `pred_label`, `confidence`, `correct`)

## 미션 6. 내가 그린 파이프라인을 설명합니다

### 1. 5일차에 Keypoint 원본을 저장하고 6일차에 다시 Feature를 만드는 이유는 무엇인가요?

5일차 26번은 관절의 Pixel 좌표·이미지 정규화 좌표·Confidence를 **가공하지 않고** 저장한다.
이렇게 하면 QA(27번)에서 관절별 Confidence로 품질을 검사할 수 있고, 6일차에서 Feature 계산 방법을 바꿀 때(Step 수, 각도 포함 여부, 팀 Feature 추가 등) **영상에서 YOLO를 다시 돌리지 않고** Keypoint CSV만 다시 읽어 새로 만들 수 있다.
실제로 6일차 38·39번 비교 실험과 3팀 45-D 실험도 같은 Keypoint CSV에서 Feature만 바꿔 계산했다.
처음부터 38-D만 저장했다면 원본 좌표가 사라져 다른 방식으로 다시 계산할 수 없다.

### 2. 4일차 22번에서 이미 만든 38-D Sequence와 5·6일차 데이터셋은 어떤 관계인가요?

**계산 방법은 같고, 데이터와 역할이 다르다.**
4일차 22번은 한 사람의 6개 영상을 Frame마다 38-D(정규화 좌표 34 + 각도 4)로 바꿔, Sequence가 무엇인지 이해하기 위한 결과였다.
5·6일차는 3명의 18개 영상으로 원본 Keypoint를 먼저 저장하고 QA·승인·사람 기준 Split을 거친 뒤, 6일차 `src/sequence_utils.py`가 **같은 38-D 계산**(같은 `normalize_by_shoulder_width`, `selected_joint_angles`)을 다시 하고 30 Step으로 맞춰 1,140개 숫자로 만든다.
그래서 4일차 결과 파일은 6일차 학습에 직접 쓰이지 않고, 4일차에서 배운 계산 방법만 이어진다.

### 3. Validation과 Test를 모델 학습에 섞으면 왜 문제가 될까요?

Validation(S02)과 Test(S03)는 **학습에 쓰지 않은 사람**에게서 모델이 잘 동작하는지 보려고 남겨 둔 데이터다.
이 데이터를 학습에 넣으면 모델이 그 사람의 체형·동작 습관까지 외워 점수가 실제보다 높게 나오고(Data Leakage), 처음 보는 사람에 대한 성능을 알 수 없게 된다.
Validation은 조건(Feature, 설정)을 고를 때만, Test는 조건을 정한 뒤 **마지막에 한 번만** 사용해야 Test 점수를 믿을 수 있다.
5일차 32번에서 Frame을 랜덤으로 나눴을 때 3명·18개 Clip이 모두 Train과 Test에 섞이는 것을 직접 확인했다.

### 4. `.pt`와 `.joblib`은 이번 프로젝트에서 역할이 어떻게 다른가요?

| | `yolo11n-pose.pt` | `rf_action_baseline.joblib` |
|---|---|---|
| 무엇인가 | 미리 학습된 **YOLO Pose 모델** (PyTorch) | 우리가 6일차 35번에서 **직접 학습한 Random Forest** (scikit-learn) |
| 입력 | 영상 Frame (이미지) | Clip 하나의 1,140개 숫자 Feature |
| 출력 | 사람 BBox + COCO 17 관절 좌표·Confidence | Action 이름 (bend_return ~ wave) |
| 사용하는 코드 | 26번 (Keypoint 추출) | 36번(Validation), 40번(Test) |

즉 `.pt`는 **"관절이 어디 있는가"**를 찾고, `.joblib`은 그 관절 움직임을 보고 **"어떤 동작인가"**를 판단한다.

### 5. 최종 혼동행렬에서 실제 정답과 AI 예측은 어떤 파일에서 왔나요?

- **실제 정답**: `configs/action_classes.csv`의 `action_label`에서 시작해 26번 Keypoint CSV → 29번 승인 목록 → 30번 `data/day05/splits/test.csv` → 34번 `data/day06/sequences/test.csv`의 `action_label` 열로 이어진다. 40번이 이 열을 `y_true`로 읽는다.
- **AI 예측**: 40번이 `data/day06/sequences/test.csv`의 1,140개 Feature를 `artifacts/day06/rf_action_baseline.joblib`(Feature 순서는 `rf_feature_columns.json`)에 넣어 `model.predict()`로 만든 `y_pred`다.
- 두 값을 비교한 결과가 `reports/day06/metrics/test_predictions.csv`(`true_label`, `pred_label`)와 `reports/day06/confusion/test_confusion_matrix.png`에 저장된다. (이번 S03 Test: 6개 모두 정답, Accuracy 1.0)
