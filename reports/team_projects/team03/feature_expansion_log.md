# 3팀 Feature 확장 기록 — 38-D에서 45-D까지

교재의 38-D Frame Feature(정규화 좌표 34 + 관절각도 4)로 시작해,
우리 팀 17개 이상행동에 필요한 Feature를 찾고 늘려 가며 실제 성능 변화를 확인한 과정을 날짜 순서대로 정리했다.

```text
3일차  38-D의 한계 발견 → 팀 Feature 8개 설계 (사진·영상 36개로 확인)
  ↓
4일차  강사님 3팀 추천 (+7 → 45-D) → 우리 영상에 맞게 수정 → 170개 영상에 계산
  ↓
6일차  Random Forest로 38-D vs 45-D 비교 → 한 단계씩 늘려 보기 → 처음 보는 사람(S05) Test
```

결론부터 말하면, **팀 Feature를 넣자 Validation(S04)은 0.6176 → 0.7353, 처음 보는 사람(S05) Test는 0.5882 → 0.6471로 올랐다.**
Feature를 한 단계씩 늘릴 때마다 Validation Macro F1이 꾸준히 올랐지만, 동작별로 보면 좋아진 동작과 나빠진 동작이 섞여 있었다.

> 2026-11-23 팀에서 사람 ID와 동작 이름을 통일해 데이터 전체의 이름을 바꾸고 6일차를 다시 학습했다.
> 이름표만 바뀌고 영상·Keypoint·Feature 값은 그대로지만, 번호 기준 Split(S01~S03 / S04 / S05)에 들어가는 사람이 바뀌어 아래 숫자는 모두 새로 학습한 결과다.

## 1단계 (3일차) — 38-D만으로는 무엇이 부족한가

3일차 Mini Challenge에서 대표 Target "바닥에 누운 자세"와 Contrast "서기"를 비교했다. (`reports/day03/challenge/feature_design.md`)

### 발견 1. 관절각도는 "몸이 누웠는지"를 알려 주지 않는다

| 관절 | 서기 | 눕기 |
|---|---|---|
| 무릎 | 161~173° | 159~164° |

서 있을 때와 누웠을 때 모두 무릎이 펴져 있어서 각도만으로는 구분이 안 됐다.
관절각도는 "얼마나 굽혔는지"만 알려 주고, 몸이 세로인지 가로인지는 알려 주지 않는다.

### 발견 2. 측면 카메라에서는 어깨 폭 정규화가 흔들린다

| 비교 | 어깨 폭 (Near / Far) | 어깨 폭 정규화 거리 | 상체 길이 정규화 거리 |
|---|---|---|---|
| 눕기 Near / Far | 124.91 / **18.99** px | **8.199** | 0.438 |
| 서기 Near / Far | 71.84 / 76.14 px | 1.113 | 0.167 |
| 눕기 vs 서기 | — | 3.518 | **1.209** |

옆에서 보면 두 어깨가 겹쳐 어깨 폭이 19px까지 줄고, 그 값으로 나눈 좌표가 크게 튀었다.
**상체 길이(어깨 중심~골반 중심)로 나누면** 같은 자세끼리는 차이가 작고(0.17~0.44), 다른 자세끼리는 차이가 크게(1.21) 남았다.
→ 이후 팀 Feature는 모두 **상체 길이**를 기준 길이로 쓰기로 했다.

### 발견 3. 동작 그룹마다 필요한 정보가 다르다

팀 Feature 8개를 만들어(`src/team_features.py`) 17개 동작 대표 장면과 영상 36개에 적용했다.

| 그룹 | 잘 설명한 Feature | 근거 |
|---|---|---|
| 눕기·쓰러짐 | 상체 기울기 + 골반-발목 높이 | 뒤로 넘어지기 영상에서 상체 기울기 서기 7.1° → 누움 84.1° → 일어남 1.4° |
| 숙이기·앉기 | 상체 기울기 + 골반-발목 높이 | 상체 기울기만 보면 구토(77.8°)·넘어지기(92.9°)도 "눕기"가 됨 |
| 내려치기 | 팔 올림 | 측면 p95 0.582 |
| 던지기 | 손목 속도 | 측면 p95 11.96 (서서 하는 동작 중 가장 빠름) |
| 차기 | 발목 속도 | 측면 p95 10.48 (사진 한 장의 두 발목 높이 차로는 놓침) |
| 몸통박치기 | 골반 속도 | 측면 p95 3.03 |
| 흔들기·밀치기 | 없음 | Pose만으로는 구분이 어려움 → 물체 위치 필요 |

3일차 끝에 "다음에 추가할 것"으로 **골반과 바닥의 상대 높이**, **Confidence가 높은 Frame만 쓴 속도**, **물체(키오스크·문 등)와의 거리**를 적어 두었다.

## 2단계 (4일차) — 강사님 3팀 추천 Feature를 우리 영상에 맞추기

4일차 `RGB영상_전처리_Sequence_Dataset` 문서에서 강사님이 3팀에 **+7개 → 45-D**를 추천했다.
"드러눕기와 앉기, 발을 들기와 문을 차는 동작은 자세뿐 아니라 공간적 관계와 움직임을 함께 봐야 하기 때문"이라는 이유였다.

| 강사님 추천 | 개수 | 우리가 만든 Feature | 바꾼 점과 이유 |
|---|---|---|---|
| 상체 기울기 | 1 | `torso_tilt_deg` | 3일차 것 그대로 |
| 사람 BBox 종횡비 | 1 | `bbox_aspect_ratio` | 3일차 것 그대로 |
| 골반과 바닥의 상대 높이 | 1 | `hip_floor_height` | 3일차 "다음에 추가할 것"에 적어 둔 항목. 3일차 `hip_ankle_dy`(골반-발목)는 발목 위치가 필요해 측면에서 발목이 가려지면 계산이 흔들리므로, **BBox 아래 끝(몸의 가장 낮은 점)**을 바닥으로 보고 새로 정의 |
| 양발목 속도 | 2 | `left_ankle_speed`, `right_ankle_speed` | 3일차는 두 발목 중 빠른 쪽 1개 → **왼쪽·오른쪽 2개**로 분리 |
| 양발과 문 사이 거리 | 2 | `left_wrist_speed`, `right_wrist_speed` | 촬영 장소(강의실)에 문·키오스크·냉동고가 없어 거리를 계산할 수 없음. 우리 동작에는 손을 빠르게 쓰는 이상행동이 6개라, 강사님 표의 "팔 동작 속도가 중요할 때 좌·우 손목 속도 +2"로 대체 |

계산 방식도 3일차에서 바꿨다.

- 속도: 3일차는 바로 앞 Frame과 비교했는데, 60fps 영상에서 관절 좌표 떨림이 속도로 잡혀 바닥 동작 p95가 20~40까지 튀었다. → **0.1초(6 Frame) 간격**으로 비교하고, 영상의 상체 길이 중앙값으로 나눴다.
- 원본 위치 보존: 강사님 안내대로 Keypoint CSV에 **원본 Pixel 좌표·관절별 Confidence·BBox 좌표**를 함께 저장해, Feature를 다시 계산할 수 있게 했다.

구현: `scripts/team03/team_build_feature_sequences.py` → 170개 영상, 70,159 Frame 중 45-D 성공 68,813

## 3단계 (4일차) — 계산한 값이 동작을 실제로 구분하는지 확인

동작 구간(`in_action`) 안에서 사람 5명의 중앙값을 동작별로 비교했다. (`reports/team_projects/team03/tables/feature_by_action.csv`)

| 동작 (측면) | BBox 비율 | 골반-바닥 높이 | 손목 속도 p95 | 발목 속도 p95 |
|---|---:|---:|---:|---:|
| 키오스크 두드리기 | 0.51 | 1.65 | **8.36** | 1.64 |
| 한손 물건 던지기 | 0.52 | 1.64 | **9.51** | 1.35 |
| 앞차기 | 0.75 | 1.63 | 4.27 | **6.64** |
| 밀치기 | 0.74 | 1.56 | 4.25 | 2.48 |
| 몸통 박치기 | 0.53 | 1.54 | 3.10 | 4.72 |
| 앞으로 눕기 | **3.19** | **0.39** | 3.55 | 3.62 |
| 뒤로 눕기 | **3.01** | **0.32** | 7.26 | 3.24 |
| 뒤로 넘어지기 | **2.36** | **0.53** | 8.25 | 4.00 |

- 측면에서 누운 동작은 BBox 비율 2.4~3.2, 골반-바닥 높이 0.3~0.5로 서서 하는 동작(약 0.5 / 1.6)과 확실히 달랐다.
- 서서 하는 동작 중에서는 손목 속도가 던지기·두드리기에서, 발목 속도가 앞차기에서 가장 높았다. (누운 동작은 쓰러지고 일어나는 동안 손목도 빠르게 움직여 값이 높게 나왔다.)
- 정면에서는 카메라 쪽으로 누우면 몸이 짧아 보여 BBox 비율이 0.75~0.83에 머물렀다. → 정면·측면을 함께 써야 한다.

여기까지는 "값이 다르다"는 것만 확인한 단계라, 실제로 모델 성능을 올리는지는 6일차에서 학습으로 확인했다.

## 4단계 (6일차) — 학습으로 효과 확인

조건: 교재 6일차와 같은 Random Forest(300 Tree, random_state 42, class_weight balanced), 30 Step Sequence,
Train S01~S03 (102개) / Validation S04 (34개). Feature 구성 **한 가지만** 바꿨다.
(`scripts/team03/team_day06_baseline.py`, `scripts/team03/team_feature_steps.py`)

### 4-1. 38-D vs 45-D

| Frame Feature | Sequence Feature | Validation Accuracy | Macro F1 | 오답 |
|---|---:|---:|---:|---:|
| 38-D (교재) | 1,140 | 0.6176 | 0.6235 | 13 / 34 |
| 45-D (팀) | 1,350 | **0.7353** | **0.7196** | 9 / 34 |

참고로 같은 조건에서 **관절각도 4개를 빼면** Accuracy는 0.6176으로 같았지만 Macro F1이 0.5905로 떨어졌다. 3일차에 "각도로는 눕기를 구분 못 한다"고 했지만, 앉기·차기처럼 굽히는 동작에는 각도가 여전히 도움이 됐다.

### 4-2. 한 단계씩 늘려 보기

| 단계 | 추가한 Feature | Frame Feature | Accuracy | Macro F1 | 오답 |
|---|---|---:|---:|---:|---:|
| 0 | (교재) | 38 | 0.6176 | 0.6235 | 13 |
| 1 | + 상체 기울기, BBox 비율, 골반-바닥 높이 | 41 | 0.6765 | 0.6784 | 11 |
| 2 | + 양발목 속도 | 43 | 0.7059 | 0.7098 | 10 |
| 3 | + 양손목 속도 | 45 | **0.7353** | **0.7196** | 9 |
| 비교 | 38 + 속도 4개만 (자세 3개 없이) | 42 | 0.6765 | 0.6765 | 11 |

- 한 단계씩 넣을 때마다 오답이 13 → 11 → 10 → 9개로 줄었다.
- **자세 3개**를 넣자 위에 앉기·앞차기가 좋아졌다.
- **발목 속도**를 넣자 휘두르기·몸통 박치기·잡고 흔들기·구토가 좋아졌다. 대신 앞차기는 다시 1개 틀렸다.
- **손목 속도**를 넣자 그때까지 한 번도 못 맞힌 샷건(0 → 0.667)과 앞차기가 좋아졌다. 대신 휘두르기(1.000 → 0.500)와 넘어지기 2개는 떨어졌다.
- 속도 4개만 넣은 42-D(0.6765)는 자세 3개까지 넣은 45-D보다 낮았다. 속도와 자세 Feature가 **함께 있을 때** 효과가 컸다.

### 4-3. 동작별 F1 변화 (38-D → 45-D)

| 좋아진 동작 | F1 | 나빠진 동작 | F1 |
|---|---|---|---|
| 샷건 | 0.000 → **0.667** | 뒤로 넘어지기 | 1.000 → 0.667 |
| 잡고 흔들기 | 0.000 → 0.500 | 앞으로 넘어지기 | 1.000 → 0.800 |
| 앞차기 | 0.667 → **1.000** | | |
| 몸통 박치기 | 0.667 → **1.000** | | |
| 위에 앉기 | 0.800 → **1.000** | | |
| 구토 | 0.667 → 0.800 | | |

- 밀치기는 38-D와 45-D 모두 F1 0이었다. 잡고 흔들기·샷건과 자세·속도가 비슷해 Pose Feature로는 끝까지 구분하지 못했다.

### 4-4. 예측이 바뀐 Clip

| Clip | 정답 | 38-D 예측 | 45-D 예측 |
|---|---|---|---|
| S04_A003_T01 | 앞차기 | 위에 앉기 (0.173) | **정답 (0.183)** |
| S04_A004_T01 | 잡고 흔들기 | 샷건 (0.223) | **정답 (0.177)** |
| S04_A004_T02 | 잡고 흔들기 | 밀치기 (0.233) | **정답 (0.250)** |
| S04_A011_T02 | 몸통 박치기 | 휘두르기 (0.177) | **정답 (0.230)** |
| S04_A013_T01 | 샷건 | 구토 (0.190) | **정답 (0.157)** |
| S04_A001_T02 | 키오스크 두드리기 | 밀치기 | 휘두르기 |
| S04_A005_T01 | 밀치기 | 샷건 | 잡고 흔들기 |
| S04_A016_T02 | 뒤로 넘어지기 | 정답 (0.213) | 앞으로 넘어지기 (0.183) |

- 8개가 바뀌어 5개가 정답이 되고 1개가 새로 틀렸다.
- 정답이 된 5개 중 4개는 팔·다리를 빠르게 쓰는 서서 하는 동작이었다. 속도 Feature가 이 동작들을 나누는 데 도움이 된 것으로 보인다.
- 새로 틀린 1개는 뒤로 넘어지기 → 앞으로 넘어지기로, 같은 "쓰러짐" 그룹 안에서 방향을 헷갈린 경우다.

### 4-5. 모델이 팀 Feature를 실제로 썼는가 (45-D 모델의 Feature 중요도)

| Feature 종류 | 중요도 합 | Frame Feature 1개당 |
|---|---:|---:|
| 정규화 좌표 34개 | 0.657 | 0.019 |
| 관절각도 4개 | 0.106 | 0.026 |
| 팀 Feature 7개 | 0.238 | **0.034** |

팀 Feature는 개수로는 45개 중 7개(16%)지만 중요도는 24%를 차지했다. Feature 하나당 중요도로는 정규화 좌표의 약 1.8배, 관절각도보다도 높았다.
7개 중에서는 골반-바닥 높이(0.040)가 가장 컸다.

## 5단계 (6일차) — 처음 보는 사람(S05)으로 최종 확인

조건은 Test를 보기 전에 정한 기준(**Validation Macro F1이 가장 높은 조건**)으로 골랐다.
4-1의 비교(38-D, Static, 좌표만, 45-D, 동작 구간만, 정면만, 측면만) 중 45-D가 가장 높아 45-D로 정했다.

| | Test Accuracy | Test Macro F1 | 정답 |
|---|---:|---:|---:|
| 38-D (참고) | 0.5882 | 0.5652 | 20 / 34 |
| **45-D (최종)** | **0.6471** | **0.6020** | 22 / 34 |

- 처음 보는 사람(S05)에서도 45-D가 38-D보다 2개 더 맞혔다. 팀 Feature의 효과가 Validation 한 사람에게만 맞춘 결과는 아니었다.
- 하지만 Validation(0.7353)보다 Test(0.6471)가 크게 낮았다. S05의 휘두르기·밀치기·앞차기·샷건·잡고 흔들기 6개를 모델이 "몸통 박치기"로 답했고, 옆으로 쓰러지기 2개는 "바닥에 앉기"로 답했다.
- 같은 방법이라도 **테스트하는 사람이 누구냐에 따라 10%p 넘게 달라진다.** 사람 한 명으로 낸 점수는 믿기 어렵다는 뜻이라, 5명을 한 번씩 Test로 빼서 평균을 내는 평가가 필요하다.

> 이름 변경 전(Train 사람 구성이 달랐을 때)에는 Validation에서 43-D가 45-D보다 조금 높았다.
> 이번 Split에서는 45-D가 가장 높아, 손목 속도까지 넣은 45-D를 유지했다.

## 6. 정리 — Feature를 늘리며 배운 점

1. **문제를 먼저 찾고 Feature를 넣었다.** 3일차에 "각도로는 눕기를 못 구분한다", "측면에서 어깨 폭이 흔들린다"를 확인했기 때문에 상체 기울기·골반 높이·상체 길이 기준을 고를 수 있었다.
2. **값이 다르다는 것과 성능이 오른다는 것은 따로 확인해야 했다.** 전체 점수는 올라도 손목 속도를 넣자 휘두르기·넘어지기는 떨어졌다.
3. **한 번에 하나씩 늘려야 무엇이 효과인지 알 수 있었다.** 45-D만 비교했다면 어떤 Feature가 어떤 동작을 좋게·나쁘게 했는지 몰랐을 것이다.
4. **평가하는 사람이 바뀌면 결론의 세기도 바뀐다.** Split 사람 구성이 바뀌자 43-D와 45-D의 순서가 뒤집혔고 Test 점수도 10%p 넘게 달라졌다. 데이터가 작을 때는 사람을 돌아가며 평가해야 한다.
5. **남은 문제는 Feature 개수가 아니라 정보의 종류다.** 밀치기 ↔ 잡고 흔들기 ↔ 샷건처럼 팔로 하는 동작끼리의 혼동은 Pose만으로 풀리지 않았다. 물체(키오스크·뽑기기계·테이블) 위치와 손 사이의 관계가 필요하다.

## 7. 다음에 할 것

- 5명을 한 명씩 Test로 빼는 평가로 38-D·43-D·45-D를 다시 비교
- 물체 위치(ROI 또는 객체 검출)를 확보해 **손목·발목과 물체 사이 거리** Feature 추가 (강사님 원래 추천)
- Confidence가 낮은 Frame을 뺀 속도 계산
- 정상행동 비교 영상을 찍어 "정상 vs 이상" 구분에서도 팀 Feature 효과 확인
